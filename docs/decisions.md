# 決めたことと理由

迷ったところを自分で決めた記録です。新しいものを下に足します。

## 2026-11-02

- **リポジトリ全体を GPL-2.0-or-later にする**。`plugin/` は EC-CUBE(GPL-2.0)に合わせる必要があり、部品ごとにライセンスを分けると読む人が迷うため、全体を 1 つにそろえた
- **受け口は店の公開ディレクトリ直下の `self-harden.php` に置く**。EC-CUBE 4.2 は店のルート = 公開ディレクトリで、既にあるファイルはそのまま配信される。プラグインのディレクトリの中に置くと EC-CUBE の `.htaccess` の決まりやプラグインの無効化に巻き込まれ、「EC-CUBE が死んでも動く」を守れない
- **鍵・退避・nonce は `var/self-harden/` に置く**。EC-CUBE 4.2 の `.htaccess` で Web から見えない場所。`var/cache` と違い、キャッシュ削除で消えない
- **署名は HMAC-SHA256 の共有鍵**。レンタルサーバーの PHP で追加の拡張なしに確実に使え、両方向(API→受け口、店→API)を同じ形で書ける。公開鍵方式は鍵の交換の手間に見合う得がこの形では小さい
- **返事にも署名を付ける**。http のままの店もあるので、途中で書き換えられた返事で AI が判断しないように
- **root の `.htaccess` の 500 は受け口の中で戻す**。root の `.htaccess` が壊れると受け口自身も 500 になり、次のリクエストでは戻せない。だから書いた同じリクエストの中で店を開き直し、だめならその場で戻す
- **書く中身に「PHP に別のファイルや形式を動かさせる指示」を入れさせない**。鍵が漏れたときに受け口が任意コード実行の道具にならないため。守りの手の答えを書き込むものではなく、受け口自身の守り
- **外から確かめるのは API が直接やる**(`http_get`)。受け口が自分で自分を見るより、お客さんと同じ道で確かめるほうが本物に近い。受け口側の確かめは、上の「同じリクエストの中で戻す」だけに使う
