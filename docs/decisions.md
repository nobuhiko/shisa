# 決めたことと理由

迷ったところを自分で決めた記録です。新しいものを下に足します。

## 2026-11-02

- **リポジトリ全体を GPL-2.0-or-later にする**。`plugin/` は EC-CUBE(GPL-2.0)に合わせる必要があり、部品ごとにライセンスを分けると読む人が迷うため、全体を 1 つにそろえた
- **受け口は店の公開ディレクトリ直下の `self-harden.php` に置く**。EC-CUBE 4.2 は店のルート = 公開ディレクトリで、既にあるファイルはそのまま配信される。プラグインのディレクトリの中に置くと EC-CUBE の `.htaccess` の決まりやプラグインの無効化に巻き込まれ、「EC-CUBE が死んでも動く」を守れない
- **鍵・退避・nonce は `var/self-harden/` に置く**。EC-CUBE 4.2 の `.htaccess` で Web から見えない場所。`var/cache` と違い、キャッシュ削除で消えない
- **署名は HMAC-SHA256 の共有鍵**。レンタルサーバーの PHP で追加の拡張なしに確実に使え、両方向(API→受け口、店→API)を同じ形で書ける。公開鍵方式は鍵の交換の手間に見合う得がこの形では小さい
- **返事にも署名を付ける**。http のままの店もあるので、途中で書き換えられた返事で AI が判断しないように
- **root の `.htaccess` の 500 は受け口の中で戻す**。root の `.htaccess` が壊れると受け口自身も 500 になり、次のリクエストでは戻せない。だから書いた同じリクエストの中で店を開き直し、だめならその場で戻す
- **書く中身に「PHP に別のファイルや形式を動かさせる指示」を入れさせない**。鍵が漏れたときに受け口が任意コード実行の道具にならないため。守りの手の答えを書き込むものではなく、受け口自身の守り
- **外から確かめるのは API が直接やる**(`http_get`)。受け口が自分で自分を見るより、お客さんと同じ道で確かめるほうが本物に近い。受け口側の確かめは、上の「同じリクエストの中で戻す」だけに使う
- **デモ用サーバーは最低限**。mod_php と FPM で `.htaccess` と `.user.ini` の効き方が逆になること、EC-CUBE 4.2.0 の管理画面が開くことまでで切り上げる。作品の価値は Agent の側にある
- **PHP は 8.1.10 に固定**。EC-CUBE 4.2.0 の公開日の時点の 8.1 系。bullseye のセキュリティ配布が archive.debian.org に移っていたので、拡張を入れるときだけ取得先をそちらに向けた
- **DB は SQLite**。部品が一番少なく、`docker compose down -v` で初期状態に戻せる
- **Web の PHP にだけ exec 系の停止を読ませる**。EC-CUBE の CLI のインストールが子プロセスを使うため。mod_php は Apache の envvars、FPM はコンテナの環境で `PHP_INI_SCAN_DIR` に Web 用の設定を足している
- **鍵はシェルの環境変数ではなく `self-harden/.env` から読む**(本人の指定)。API は docker compose の `env_file` で読む。読めているかは「キーがあるか」だけ確かめ、値は出さない
- **受け口の設定は `<?php exit; ?>` の 1 行のあとに JSON**。受け口は `include` を持たないので、PHP の配列を返す形は読めない。Web から開かれても 1 行目で止まる
- **API は TypeScript + Hono + 公式 SDK、署名は WebCrypto**。Node でも Workers でも同じコードが動く。保存先だけを差し替える形にした(いまはファイル)
- **Agent は 1 歩ずつ保存する**。1 歩 = Claude を 1 回呼び、出てきた道具を実行して保存。止まっても次の 1 歩から続けられる。`wait` は「次の 1 歩を何秒後に回すか」を保存するだけで、店には何も残らない
- **モデルは `claude-opus-5-5`、考える深さは high、web search / web fetch は Anthropic のサーバーの道具を使う**。公開の情報を自分で当たるため。断られたとき用に `fallbacks: "default"` を付けた
- **プロンプトには役目と進め方だけを書く**。特定の脆弱性、回避策、サーバーの癖(どこで何が効くか、いつ効くか)は書かない。「試して確かめる」「効いたのを見てから終わる」という一般の進め方だけを書く
- **小部屋の試しは `lab_test` の 1 つの道具にまとめた**(書く → 合言葉 → 外から probe を開く)。中身は Agent が決める。道具は手順をまとめるだけ
- **本番に書くときは、いつも店のトップと受け口自身を開いて確かめる**(`verify` を API 側で必ず付ける)
- **プラグインは DB を使わない**。鍵は受け口と同じ `var/self-harden/config.php` に置く。無効にしても受け口は残す(EC-CUBE が死んでも動く命綱)。削除で受け口・鍵・小部屋を消し、退避ファイルは人が手で戻せるように残す
- **店 → API の呼び出しはプラグインのコントローラーから**(ブラウザから API を直接呼ばない)。鍵をブラウザに出さず、CORS も要らない
- **登録し直すときは前の鍵で署名させる**。他人が同じ店の ID で登録を上書きできないように
- **書く中身の決まりは「新しく足す行」にだけ当てる**(一周目で見つかった)。最初は `AddType` や `RewriteRule` の種類の指定を全部断っていたので、EC-CUBE がもともと書いている webp の行まで消さないと書けず、Agent が元の行を外してしまった。PHP や CGI として動かすものだけを断り、今のファイルにある行は残せるようにした
- **点検は押されなくても始まる**(本人の指摘)。店がつながったら最初の点検を始め、そのあとは API が決まった間隔(既定 24 時間、`SH_AUTO_INTERVAL_HOURS`)で自分で始める。管理画面は開くだけで、いま動いている点検の経過と結果が流れる。通知の URL を貼るのは、外からきっかけを渡すための入口の 1 つ
- **API が再起動しても点検は続きから**。起動時に `running` の点検を拾って回し直す(1 歩ずつ保存しているので、最後に保存した 1 歩の次から)
- **本体の PHP のファイルは、受け口が自分で公式から取ってきて書く**(2 本目の指示から変えたところ)。指示は「API が公式の配布物を取ってきて受け口に書かせる」だったが、それだと鍵が漏れたときに API を通さず好きな PHP を書けてしまい、「任意のコードを実行させない」が崩れる。API(と Agent)が渡すのは「どのファイルを、公式のどの版にするか」だけにし、中身は受け口が `raw.githubusercontent.com` の決まった置き場から取る。公式の一覧(ファイルごとの SHA-256)は指示どおり API が公式リリースから作り、同じ版に戻すときは受け口に SHA-256 の一致も確かめさせる
- **部品(vendor/)は composer.lock に書かれた GitHub の置き場から**。ロックされた版か、同じメジャー版の新しいタグだけ。`composer.lock` は受け口から書けないので、取得元をすり替えられない
- **書く・隔離する・読むで外す場所を 1 つの関数(`sh_is_protected`)にまとめた**。`var/`、受け口自身、小部屋、`.env*`、`composer.json` / `composer.lock`、`.git`
- **画面に出す一言は道具の `note`(必須)**。プロンプトで念を押す代わりに、全部の道具に店の人向けの一言を必須にした。かなを含まないものは `claude-haiku-5-5` で日本語にしてから出す。道具を呼ぶ発言の本文は note と重なるので画面には出さない
- **`.htaccess` の元の行を消すなら理由が要る**。API が今の中身と比べ、消える行があれば `allow_removing_lines` と理由が無い限り書かない。書いたら足した行と消した行を結果に出す
- **点検の途中で貼られた通知は受け箱に入れる**。最初は点検の記録に書き足していたが、回っている 1 歩が古い記録で上書きして通知が消えた(実際に起きた)。受け箱を分け、1 歩ごとに取り出して渡す
- **デモ用サーバーに無害な仕込みを入れる**(`demo-servers/common/plant-demo.sh`)。本体の 1 ファイルに特定のクエリで見出しを 1 つ足すだけの行、公開ディレクトリに ok と出すだけの PHP。照らし合わせが見つけられるかを確かめるため
- **鍵は使う人それぞれのもの(BYOK)**。OSS なので、店の人や制作会社が自分の API キーで自分の API を動かす。調べた結果の使い回し(版・部品・通知ごとに 7 日)は、その API の中だけの控えで、ほかの人とは共有しない。費用は点検ごとに API の記録に残すが、管理画面には出さない
- **鍵が漏れても API を呼び放題にさせない**。1 回の点検の費用の上限(`SH_RUN_BUDGET_USD`、既定 $6。超えたら報告を出して終える)、店ごとの 24 時間の回数と費用の上限(`SH_SHOP_DAILY_RUNS` 6 回、`SH_SHOP_DAILY_USD` $15)。漏れた鍵で使えるのはその店の枠だけ
- **環境変数で FastCGI に PHP の設定を渡す書き方は断る**(点検の中で見つかった)。ロリポップ風の点検で、Agent が `.htaccess` の `SetEnv PHP_VALUE` / `PHP_ADMIN_VALUE` を使い、FPM でも `.htaccess` から PHP の設定を変えた。受け口の決まりは `php_value` の行しか見ていなかったので、`SetEnv PHP_ADMIN_VALUE "auto_prepend_file=…"` が素通りしていた(鍵が漏れたときにアップロードされたファイルを PHP として読ませる道になる)。`php_value` / `php_flag` の命令以外で PHP_VALUE / PHP_ADMIN_VALUE を含む行は、書き方を問わず断る
- **ロリポップ風のデモ用サーバーでは、PHP_VALUE / PHP_ADMIN_VALUE を FPM に渡さない**。httpd の既定では `.htaccess` の `SetEnv` がそのまま FastCGI の値として FPM に渡り、利用者が管理者向けの設定まで変えられてしまう。共用のレンタルサーバーはこれを渡さないので、`ProxyFCGISetEnvIf "true" !PHP_VALUE` などで消して本物に合わせた。なお FPM は、一度受け取ったこの値を worker が持ち越すので、直したあとは FPM の再起動が要った
- **受け口のテストでは、受け口が確かめに開く先を 2 つ目の `php -S` にする**。PHP 7.4 の `php -S` は、複数の worker が試験的で、自分自身への呼び出しで時間切れになることがあった(受け口は正しく戻していた)
