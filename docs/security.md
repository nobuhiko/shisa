# 受け口の守り

守る道具が裏口になったら終わりなので、受け口(`self-harden.php`)は「鍵を持たない人には何もできない」「鍵を持っていても決まったことしかできない」の 2 段で作っています。テストは `plugin/tests/run.sh`(PHP 8.1 と 7.4 で 207 件)。

## 形

- 素の PHP 1 枚。EC-CUBE も Composer も読み込まない。ほかのファイルを `include` しない
- 操作は決まった種類だけ(`ping` `inspect` `list_dir` `read_file` `write_file` `restore` `list_backups` `lab_arm` `hash_tree` `restore_official` `quarantine` `release_quarantine` `list_quarantine` `audit_tail`)。コードを渡して動かす操作は無い
- **本体の PHP のファイルを書くときは、中身を受け口が自分で決まった公式の場所から取ってくる**(`restore_official`)。API が渡せるのは「どのファイルを、公式のどの版にするか」だけで、中身も URL も渡せない。鍵が漏れても、書けるのは公式の中身だけ
- 鍵は `var/self-harden/config.php`。1 行目が PHP の `exit` なので、Web から開かれても中身は出ない。受け口は `include` せずに文字として読む
- `var/self-harden/` には `Require all denied` の `.htaccess` も置く

## 考えた攻撃と防ぎ方

| 攻撃 | 防ぎ方 | テスト |
|---|---|---|
| 署名なしで操作を呼ぶ | 見出しが 1 つでも欠けたら 401。理由は返さない | 署名なしは 401 / 署名の見出しだけ欠けても 401 |
| 本文を書き換える | 署名に本文の SHA-256 を含める | 本文を書き換えたら 401 |
| 鍵を推測する・別の店の鍵を使う | 店ごとに 32 バイトの乱数の鍵。`hash_equals` で比べる | 違う鍵 / 違う店の ID |
| 盗み見たリクエストをあとで送る | 時刻は前後 300 秒まで。nonce は 1 回きり(`fopen 'x'` で原子的に記録) | 301 秒前 / 301 秒先 / 使い回し |
| 偽物のリクエストで nonce の置き場を埋める | 署名が通ったものだけ記録する。nonce の形は 16 進数だけ | nonce の形がおかしければ 401 |
| 決まった場所の外に書く(`../`、絶対パス、NUL) | 書き先は論理名(`root/.htaccess` など)で受け、決まった 4 つと「既にあるディレクトリの `.htaccess`」だけ | 「書けない: …」15 件 |
| シンボリックリンクで外に出る | パスの各段で `is_link` を見て、たどらない。書き先そのものがリンクでも断る | 書き先がシンボリックリンク / `dir:linkdir` |
| 鍵や秘密を読み出す | 読めるファイルは名前で決める(`.htaccess` `.user.ini` `composer.*` など)。`.env` は値を伏せた形でだけ返す | 読めない: … / .env の秘密は伏せる |
| 鍵が漏れたときに、受け口で PHP のコードを動かす | `.htaccess` / `.user.ini` に、PHP に別のファイルを読ませる・別の形式を PHP や CGI として動かす・ログやセッションを公開の場所に書かせる指示を、**新しく足す**ことはさせない(`auto_prepend_file`、PHP/CGI/FPM を指す `SetHandler`・`AddType`、`Action`、`error_log`、`session.save_path` など)。画像の種類の指定のように PHP と関係のない行は通す。今のファイルに**もともとある行**は決まりの外として残せる(店の人や EC-CUBE が書いたもの。受け口から新しく作ることはできないので、残せても新しい力にはならない) | 断る 0〜21 / 通す 0〜2 / もともとある行 |
| 退避ファイルを書き換えて、戻すときに任意の場所に書かせる | 戻すときも、退避に書かれた場所が決まりの中かを確かめ直す | 退避に書かれた場所が決まりの外なら戻さない |
| 小部屋の確認用 PHP を悪用する | 中身は受け口に埋め込んだ固定の文字列。合言葉は 32 バイト、120 秒、1 回きり。合わなければ空の 404 | 小部屋 7 件 |
| 書いた `.htaccess` で店を落とす | 書いたあと同じリクエストの中で店を開き、500 かつながらなければすぐ戻す。退避は書く前に必ず取る | 500 になったら戻す |
| 受け口自身のコードに危ない関数が紛れ込む | テストでトークン単位に調べる(`eval` `include` `exec` 系 `assert` `unserialize` バッククォートなど) | 受け口のコード 19 件 |

## 広げた手(2 本目)と考えた攻撃

| 攻撃 | 防ぎ方 | テスト |
|---|---|---|
| 鍵を持つ者が、本体に好きな PHP を書く | 本体を書く操作は `restore_official` だけ。中身は受け口が `https://raw.githubusercontent.com/` の決まった置き場から自分で取る。API から渡された `url` や `content` は使わない | API から URL や中身は渡せない |
| 公式でない取得元を指す | EC-CUBE は `EC-CUBE/ec-cube` 固定。部品は `composer.lock` に書かれた GitHub の置き場だけ(`composer.lock` は受け口から書けない)。https だけ、転送はたどらない、4MB まで | 断る: `local/nogithub`・`unknown/pkg`・`../../evil/repo/main`・URL |
| 古い版に戻して、直った弱点を戻す(ダウングレード) | EC-CUBE は今の版以上のタグか、公式のコミットの番号だけ。部品はロックされた版か、同じメジャー版の新しいタグだけ | 断る: `4.1.2`・`v2.15.1`・`v3.0.0`・`main` |
| `var/self-harden/`(鍵・退避)、受け口自身、小部屋、`.env`、`composer.*` を書き換える | `sh_is_protected` で書く・隔離する・読む(`.env` と `var/`)のどれからも外す | 断る: 各パス |
| 決まった場所の外へ書く・シンボリックリンクで外へ出る | 書けるのは `src/` `app/` `html/` `vendor/` と root 直下のふつうのファイルだけ。パスの各段で `is_link` を見る | 断る: `bin/console`・`../outside`・`linkdir` |
| 取ってきた中身が想定と違う | API が公式リリースの一覧から `expected_sha256` を渡せば、受け口が一致を確かめてから書く | 取ってきた中身が違えば書かない |
| 本体を書いて店を壊す | 退避 → 書く → 店のトップ・商品一覧・カート・受け口・管理画面を開く → 500 なら同じリクエストの中で戻す。opcache も消す | 公式に戻したものも退避から戻せる |
| 隔離を使って必要なファイルを消す・隔離の外へ動かす | 隔離は `var/self-harden/quarantine/` へ移すだけ(消さない)。移したあと店を開き、壊れたら戻す。戻し先は記録を信じず決まりで確かめ直す。元の場所に別のファイルがあれば戻さない | 隔離できない: 各パス / 戻し先が決まりの外なら戻さない / 元の場所に別のファイル |
| `SetEnv PHP_ADMIN_VALUE "auto_prepend_file=…"` のように、環境変数で FastCGI に PHP の設定を渡す(`php_value` の決まりを素通りする) | `.htaccess` の `php_value` / `php_flag` の命令の行以外で `PHP_VALUE` / `PHP_ADMIN_VALUE`(`php_value` 等の文字)を含む行は、`SetEnv`・`SetEnvIf`・`RewriteRule [E=…]`・`ProxyFCGISetEnvIf` のどれでも断る。点検の中で Agent が実際にこの書き方を使って見つかった穴 | 断る: SetEnv PHP_ADMIN_VALUE ほか 6 件 |
| `write_file` の target に `code:shell.php` を渡して、EC-CUBE の中に好きな PHP を書く(別の目の点検で見つかった。`code:` は退避から戻すために足した分岐で、`write_file` からも通れ、`.user.ini` の決まりで中身を見ていたので PHP のコードが通った。鍵が漏れたら Web シェルを置けた) | `write_file` は、行き先の名前が `.htaccess` か `.user.ini` のときだけ書く。`code:` は退避から戻す(`restore`)ときだけ受け付ける。本体のファイルを書く道は `restore_official` と `apply_official_fix`(中身は受け口が公式から取る)だけ | write_file に code:… を渡すと拒否(5 件) |
| `.htaccess` を全文置き換えて、今ある守りの行(`Require all denied`、`php_flag engine off`、`SetHandler None`、`Options -Indexes`、`<FilesMatch>` の囲み など)を消す | 本番と `dir:` の `.htaccess` では、今の中身にある守りの行が新しい中身から消えていたら断る(小部屋は試す場所なので対象外) | 守りの行を消す中身は拒否 / dir: でも / 小部屋は空に戻せる |
| コミットの番号を使って、今の版より古い中身に戻す(直った弱点を戻す) | コミットの番号のときは、受け口が自分でその時点の公式の `Constant.php` を取り、版が今の版より古ければ断る。`restore_official` と `apply_official_fix` の両方で | 古い版(4.1.2)のコミットの番号は拒否 / 新しい版は使える |
| 置き場(`var/self-harden/`)の守りの `.htaccess` を消された状態が続く | 署名が通るたびに置き直す | 署名が通るたびに置き直す |
| 名前の許可(`.htaccess`、`composer.json` など)を使って、触ってはいけない場所の中のファイルを読む | 名前の許可は、触ってはいけない場所(`var/` など)の中では効かせない(退避ファイルと小部屋は別に許す) | 名前が許可の一覧にあっても読めない(3 件) |
| 何をされたか分からない | 署名が通った操作を `var/self-harden/audit.log` に 1 行ずつ(時刻・操作・パス・結果・退避の番号)。中身と鍵は書かない。1MB で古い半分を切る | 記録が残る / 鍵や中身は書かない / 署名が通らなかった呼び出しは記録しない |

## 残る危うさ

- 鍵を持つ者は、古い退避に `restore` で戻すことで、あとから足した守りの行を外すことができる(退避から戻す操作は、壊れたときの命綱なので止めていない)。記録(`audit.log`)には残る


- **鍵が漏れたら**、その店の `.htaccess` / `.user.ini` を書き換えたり、ファイルを隔離したりして店を止めることはできる(戻すための退避と隔離は残る)。本体を公式の別のコミットの中身にすることもできる(公式のコミットの中に古いものがあれば、一部のファイルを古い形にできる。タグは今の版以上に限っているが、コミットの番号は順番を確かめていない)。自分の PHP のコードを動かすこと、決まった場所の外に書くこと、`.env` の値を読むことはできない
- **API が乗っ取られたら**、上と同じことができる。API の鍵の置き場は、手元では `api/data/`、公開するなら暗号化した保存先にする
- `.htaccess` の決まりは、全部の書き方を読み解くものではない。怪しい行は断る方に倒している。抜けが見つかったらテストに足して塞ぐ
- http の店では、通り道で中身を見られる。改ざんは署名で弾くが、中身(サーバーの設定の一覧)は見える。本番は TLS が前提
