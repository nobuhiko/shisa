# 受け口の守り

守る道具が裏口になったら終わりなので、受け口(`self-harden.php`)は「鍵を持たない人には何もできない」「鍵を持っていても決まったことしかできない」の 2 段で作っています。テストは `plugin/tests/run.sh`(PHP 8.1 と 7.4 で 114 件)。

## 形

- 素の PHP 1 枚。EC-CUBE も Composer も読み込まない。ほかのファイルを `include` しない
- 操作は 8 つだけ(`ping` `inspect` `list_dir` `read_file` `write_file` `restore` `list_backups` `lab_arm`)。コードを渡して動かす操作は無い
- 鍵は `var/self-harden/config.php`。1 行目が PHP の `exit` なので、Web から開かれても中身は出ない。受け口は `include` せずに文字として読む
- `var/self-harden/` には `Require all denied` の `.htaccess` も置く

## 考えた攻撃と防ぎ方

| 攻撃 | 防ぎ方 | テスト |
|---|---|---|
| 署名なしで操作を呼ぶ | 見出しが 1 つでも欠けたら 401。理由は返さない | 署名なしは 401 / 署名の見出しだけ欠けても 401 |
| 本文を書き換える | 署名に本文の SHA-256 を含める | 本文を書き換えたら 401 |
| 鍵を推測する・別の店の鍵を使う | 店ごとに 32 バイトの乱数の鍵。`hash_equals` で比べる | 違う鍵 / 違う店の ID |
| 盗み見たリクエストをあとで送る | 時刻は前後 300 秒まで。nonce は 1 回きり(`fopen 'x'` で原子的に記録) | 301 秒前 / 301 秒先 / 使い回し |
| 偽物のリクエストで nonce の置き場を埋める | 署名が通ったものだけ記録する。nonce の形は 16 進数だけ | nonce の形がおかしければ 401 |
| 決まった場所の外に書く(`../`、絶対パス、NUL) | 書き先は論理名(`root/.htaccess` など)で受け、決まった 4 つと「既にあるディレクトリの `.htaccess`」だけ | 「書けない: …」15 件 |
| シンボリックリンクで外に出る | パスの各段で `is_link` を見て、たどらない。書き先そのものがリンクでも断る | 書き先がシンボリックリンク / `dir:linkdir` |
| 鍵や秘密を読み出す | 読めるファイルは名前で決める(`.htaccess` `.user.ini` `composer.*` など)。`.env` は値を伏せた形でだけ返す | 読めない: … / .env の秘密は伏せる |
| 鍵が漏れたときに、受け口で PHP のコードを動かす | `.htaccess` / `.user.ini` に、PHP に別のファイルを読ませる・別の形式を PHP として動かす・ログやセッションを公開の場所に書かせる指示を書かせない(`auto_prepend_file`、`SetHandler`、`AddType`、`error_log`、`session.save_path` など) | 断る 0〜18 |
| 退避ファイルを書き換えて、戻すときに任意の場所に書かせる | 戻すときも、退避に書かれた場所が決まりの中かを確かめ直す | 退避に書かれた場所が決まりの外なら戻さない |
| 小部屋の確認用 PHP を悪用する | 中身は受け口に埋め込んだ固定の文字列。合言葉は 32 バイト、120 秒、1 回きり。合わなければ空の 404 | 小部屋 7 件 |
| 書いた `.htaccess` で店を落とす | 書いたあと同じリクエストの中で店を開き、500 かつながらなければすぐ戻す。退避は書く前に必ず取る | 500 になったら戻す |
| 受け口自身のコードに危ない関数が紛れ込む | テストでトークン単位に調べる(`eval` `include` `exec` 系 `assert` `unserialize` バッククォートなど) | 受け口のコード 19 件 |

## 残る危うさ

- **鍵が漏れたら**、その店の `.htaccess` / `.user.ini` を書き換えて店を止めることはできる(戻すための退避は残る)。PHP のコードを動かすこと、決まった場所の外に書くこと、`.env` の値を読むことはできない
- **API が乗っ取られたら**、上と同じことができる。API の鍵の置き場は、手元では `api/data/`、公開するなら暗号化した保存先にする
- `.htaccess` の決まりは、全部の書き方を読み解くものではない。怪しい行は断る方に倒している。抜けが見つかったらテストに足して塞ぐ
- http の店では、通り道で中身を見られる。改ざんは署名で弾くが、中身(サーバーの設定の一覧)は見える。本番は TLS が前提
